2. Kanban & Board: Persistência de Fluxo

Implementação de um sistema de Drag-and-Drop com persistência assíncrona. A interface reflete o banco de dados em tempo real via WebSockets.

Arquitetura de Estados

Estado 0: Backlog - Task persistida com position_index: NULL.
Estado 1: To Do - Atribuído ID de coluna. Notificação enviada ao Lead.
Estado 2: Doing - Timestamp start_at gravado para cálculos de Analytics.
Estado 3: Done - Timestamp closed_at gravado. Task movida para histórico de cache.

3. Analytics: Processamento de Dados Brutos

O motor de Analytics não apenas exibe dados, ele realiza mineração para identificar gargalos (bottlenecks).

Cumulative Flow Diagram (CFD) Logic

O gráfico utiliza dados empilhados. Se a distância vertical entre "Doing" e "Done" aumenta, o sistema dispara um Internal Event para a aba Teams sinalizando sobrecarga.

Esquema de Dados (JSON Example)

4. Teams: Gestão de Recursos e Deep Work

Diferente de CRMs comuns, o NovaTask foca na saúde mental da equipe. A métrica de Capacity Plan impede a atribuição de tarefas acima de 100% da carga horária.

Monitoramento de Deep Work

Quando o usuário ativa o Deep Work Mode, o front-end executa as seguintes ações:

  • Inibe todas as chamadas de API POST /notifications para o ID do usuário.
  • Altera o CSS do avatar para box-shadow: 0 0 15px var(--accent).
  • Adiciona uma trava de UI no Kanban impedindo que outros usuários arrastem tarefas para ele.
